UseArazzo Validator

Published

Every violation against the Arazzo specification, with the location that caused it.

An Arazzo document can parse cleanly and still be wrong: two steps sharing an ID, a goto to a step that does not exist, a runtime expression that does not parse. @usearazzo/validator finds those problems before a run does, and reports each one with its line, its severity, and the rule it broke.

From the Terminal

The UseArazzo CLI puts the Validator behind a single command, for your terminal and your CI pipeline. The first document has two steps with the same ID, an error. The second has a step without a description, a warning.

usearazzo validate 
$ npx @usearazzo/cli validate adopt-a-pet.arazzo.yaml
adopt-a-pet.arazzo.yaml
  16:9-18:38  error  9040403  Every step must have a unique 'stepId' within a workflow.
  19:9-22:1   error  9040403  Every step must have a unique 'stepId' within a workflow.

✖ 2 problems (2 errors)$ npx @usearazzo/cli validate onboarding.arazzo.yaml
onboarding.arazzo.yaml
  16:9-18:1  warning  9050201  Step 'description' should be present and non-empty string.

⚠ 1 problem (1 warning)

Need the diagnostics in your own code instead? They are one function call away. See Installation.

What It Checks

Every Arazzo object

Required fields, field types, and allowed values on every object, from the document root to criteria and actions. IDs must be unique, and the steps and workflows a document points at must exist in it. Runtime expressions must parse.

The version you wrote

Each document is checked against the Arazzo version in its own arazzo field. A dependsOn on a step passes in 1.1.0 and is reported in 1.0.1.

Diagnostics your tools understand

Every problem is a Language Server Protocol diagnostic: a range, a severity, a stable numeric code, and a message. Editors underline it, CI counts it, and your code can match on it.

Ready for untrusted documents

Only local JSON and YAML files are read. For a document you did not write, one option turns off everything beyond the document itself; another confines reads to a single directory.

The API reference lists every rule, with its code, severity, and message.

Installation

npm install @usearazzo/validator

Point it at a file or a URL, and count the errors:

import { validateURI, DiagnosticSeverity } from '@usearazzo/validator';

const diagnostics = await validateURI('./adopt-a-pet.arazzo.yaml');
const errors = diagnostics.filter((d) => d.severity === DiagnosticSeverity.Error);
const isValid = errors.length === 0;

Content already in memory, options, the shape of a diagnostic, and validating documents you do not trust are all in the API reference.
